## Контекст продукта

- Android/Flutter (`apps/mobile`) **на паузе**, не удаляем.  
- Пилот = **Telegram-бот**. Диалог главный, Mini App позже.  
- Backend уже есть: Laravel `apps/api`, Cloud `https://api-dev.autodoctor.by`, админка `/admin`.  
- Бот живёт **в том же** Laravel (webhook вроде `/telegram/webhook`), **новый репозиторий не нужен**.  
- Регистрация = `telegram_id`. Первый `/start` → рассказать про авто → выжимка → кнопка **Записать**. Без кнопки машину и журнал не писать.  
- Работы: свободный текст → дыры чеклиста (бывшие формы) → выжимка → **Записать**.  
- «Не знаю» сохраняется, слот больше не спрашивают, пока пользователь сам не вспомнит.  
- Сервер знает слоты (пусто / известно / unknown), не «память чата».  
- Темы = меню бота и `assistant_threads`, не обязательные native topics Telegram.  
- 1 автомобиль.

## Деньги и лексика — не путать

- От **топлива отказались** в продукте бота. Пользователю говорим **токены**.  
- В коде API кошелёк ещё может называться `agent_fuel_wallets` / мл — технический долг. **Не** писать в боте «топливо», «заправка», `/fuel`. Команды: `/tokens`.  
- Пока токены **бесплатны для пользователя**, платит продукт. Поэтому бот **нельзя** открывать всем.

## Первая задача (обязательный ограничитель)

Сделай **белый список** пользователей Telegram:

- допуск по числовому `telegram_user_id` (env `TELEGRAM_ALLOWLIST_IDS` и/или таблица в админке);  
- **пустой список = никто не проходит** (не «все можно»);  
- кто не в списке: шаблон «закрытый пилот», **никакого** вызова LLM и **никакого** списания токенов;  
- проверка **до** AI.

Потом по плану: скелет вебхука → первое авто → журнал работ → темы → учёт токенов. **Stars/кассу не делать**, пока не попросим.

Не коммить без согласования. Не коммитить секреты, `google-services.json`, `.hprof`, `cacert.pem`.

Начни с этапа 0 (белый список) и скелета бота, если код бота ещё не начат. Сверься с ТЗ 0.5 и планом, не выдумывай топливо.
